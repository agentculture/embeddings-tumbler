# Build Plan — embeddable space viewer

slug: `embeddable-space-viewer` · status: `exported` · from frame: `embeddable-space-viewer`

> Any site or tool can drop in embeddings-tumbler: a self-contained viewer that takes a set of embeddings and shows them as a moving 3-D window through the full-dimensional space (Tumble, Lattice, Wander). The first version is proven on a real Atlas study from embeddings-cli; vector stores, live agent conversations and photo collections feed the same data contract later.

## Tasks

### t1 — \[tumbler\] Bring the spec into the new repo: copy the exported spec, the frame state and the reference demo source into embeddings-tumbler, and replace the template CLAUDE.md/README text with what this project is

- covers: c13, h10
- acceptance:
  - docs/specs/2026-11-13-embeddable-space-viewer.md and docs/specs/reference/embedding-tumbler-demo.html exist in embeddings-tumbler and are byte-identical to the embeddings-cli copies
  - README.md and CLAUDE.md no longer describe a template; they state that no embedding viewer existed in the surveyed repos as of 2026-11-13 and name the reference file
  - markdownlint and the existing pytest suite pass

### t2 — \[tumbler\] Write the data contract: docs/data-contract.md plus fixtures under tests/fixtures/contract/ (valid 384-d and 1024-d sets, labels-only set, bumped schema version, wrong vector-block length, mixed dimension, second model id)

- covers: c3, c26, c27
- acceptance:
  - The document specifies, with field names and types: schema version, model id, dimension, item count, provenance, optional reduction record, per-point id/label/group/metadata, and the little-endian float32 vector block with its exact length rule
  - It specifies full replace and incremental append, and what is refused (unknown version, wrong block length, mixed dimension or model)
  - Every fixture is generated by a stdlib-only Python script in the repo, and a test asserts each valid fixture's vector block is exactly points x dimension x 4 bytes

### t3 — \[tumbler\] JavaScript source layout and assembler: js/src/NN-name.js modules concatenated in filename order by scripts/assemble.py into `embeddings_tumbler`/static/embeddings-tumbler.js with a version-and-source header; package.json with node's built-in test runner

- covers: c2, c27
- acceptance:
  - scripts/assemble.py is deterministic: two runs give byte-identical output, and a test fails when the committed assembled file is stale
  - The assembled file starts with a header naming the project, version and source repository, and the version equals pyproject.toml's
  - A static test fails if the assembled file contains an http(s) URL, eval, new Function or an import of another module
  - 'node --test' runs from the repo root with no installed dependency

### t4 — \[tumbler\] Core mathematics module (pure JS, no DOM): seeded random source, centring, orthonormal frames, principal directions, the guided tour generator, true nearest neighbours, local neighbourhood frames, and the group-separation measure

- depends on: t3
- covers: c30, h21, c24, c9
- acceptance:
  - Given the same data and seed, the tour returns the identical frame for the same elapsed time across two runs
  - Every frame returned is orthonormal to 1e-5 and every projection is a linear map of the centred data; no non-linear layout exists in the module
  - On a fixture with planted groups in 1024-d, the guided tour's mean group separation exceeds a uniformly random tour's by a margin asserted in the test
  - The tour reports the share of total variance held by the directions it moves through, and a test recomputes that share independently
  - All functions take dimension from their input; tests run at 384, 768, 1024 and 2560

### t5 — \[tumbler\] Contract loader and validator module (pure JS): reads records plus the float32 block, checks version, dimension and model, and merges an append into an existing set

- depends on: t2, t3
- covers: c6, h6, h18, c26, c27
- acceptance:
  - Each valid fixture loads; the bumped-version fixture is refused with a message naming the version found and the versions supported
  - A vector block of the wrong length, mixed dimensions, or an append with a different model id or dimension is refused and the existing set is returned unchanged
  - An append with new ids adds points and keeps existing ids and their order; a reduction record in the data is preserved and exposed

### t6 — \[tumbler\] Renderer module: port the reference's WebGL 2 drawing (points, true-neighbour wires, glow, bloom, depth of field, trails, twinkle) with the dimension taken from the data instead of fixed at 384

- depends on: t3
- covers: c25, h16
- acceptance:
  - No literal 384 or 96 remains in texture layout or shader source; shader loop bounds are generated from the dimension
  - A headless-browser test renders a 384-d and a 1024-d fixture to non-blank frames with no console error
  - The renderer exposes dispose() that deletes every texture, buffer, program and framebuffer it created, and handles context loss by rebuilding or reporting
  - Without WebGL 2 the renderer reports unavailability to its caller instead of throwing

### t7 — \[tumbler\] The three modes as separate modules over one mode interface: Tumble (guided tour), Lattice (true-neighbour wires, one axis swapped at a time) and Wander (neighbour-to-neighbour flight with local frames)

- depends on: t4, t6
- covers: c24
- acceptance:
  - Each mode lives in its own file and implements the same documented interface (enter, step, draw parameters, status line)
  - A test registers a fourth dummy mode without editing any existing mode file or the data contract
  - Tumble uses the guided tour from the mathematics module and exposes the variance share it tours through
  - With a fixed seed, each mode's sequence of frames over 10 simulated seconds is identical across two runs

### t8 — \[tumbler\] Viewer API module: mount(el), update(data), destroy(el); pause when hidden or off screen; provenance block; per-dimension readout strip; controls; theming from the host's CSS variables

- depends on: t5, t6, t7
- covers: c2, c14, h11, c28, c9, h5, c29
- acceptance:
  - mount changes nothing outside the given element; update(full set) replaces the view; update(append) adds points without resetting the camera or dropping points
  - Invalid data shows a plain message inside the element and does not throw into the host
  - The provenance block shows source, model, dimension, item count, seed, how the view is produced, any reduction applied, and that a projection is a shadow of the space
  - A label containing HTML markup is displayed as literal text
  - destroy stops the animation loop and releases observers and GPU resources; while document.hidden or off screen no frame work runs
  - The module contains no fetch, XMLHttpRequest, WebSocket, sendBeacon or image/script URL construction

### t9 — \[tumbler\] Built-in sample set: port the reference's synthetic generator (nine regions, filaments, bridges, month ring, temperature arc) to emit a contract-conforming data set, marked synthetic in its provenance

- depends on: t2, t4
- covers: c22
- acceptance:
  - With the reference's seed the generator yields the same point count and group names as the reference demo
  - Its output passes the contract loader, and its provenance says the data is synthetic

### t10 — \[tumbler\] Web component shell: a separate file defining <embeddings-tumbler> that calls only the public mount/update/destroy API

- depends on: t8
- covers: c2
- acceptance:
  - The file contains no rendering or projection code; a static test asserts it references only mount, update and destroy on the core object
  - Adding the element mounts a viewer, removing it destroys it, and a 'src' attribute loads a data file from the host's own origin

### t11 — \[tumbler\] Standalone page: HTML, stylesheet and page script (no inline script, no external origin) that loads a data file or the sample set and reproduces the reference's look: night sky, masthead, readout strip, controls and per-mode notes

- depends on: t8, t9
- covers: c22
- acceptance:
  - The page has no inline script or style attribute that a script-src 'self' policy would block, and references no other origin; fonts are bundled or replaced by a local stack
  - Opened with no data argument it shows the sample set; given a data file path it shows that file
  - All three modes, the provenance block and the controls from the reference are present

### t12 — \[tumbler\] CLI verbs in the Python package: write the viewer files (core, web component, standalone page) into a host folder, and serve a folder locally; both follow the agent-first rubric

- depends on: t3
- covers: c4
- acceptance:
  - The write verb previews by default, writes only with --apply, refuses existing files without --force, and supports --json
  - The serve verb binds to loopback by default, serves only static files, and neither reads nor needs any gateway key
  - 'teken cli doctor . --strict' passes, each new verb has an explain entry, and learn lists them

### t13 — \[tumbler\] Packaging and release: the wheel carries the static files; an npm package under the culture.dev organisation carries the same core file; CI runs pytest, node tests and the assembler check, and publishes both by trusted publishing

- depends on: t10, t11, t12
- acceptance:
  - A CI step fails if the core file in the built wheel and in the npm tarball are not byte-identical or their version headers differ
  - The publish workflows use the registries' trusted publishing; no registry token appears in repository secrets, workflow files or any committed file
  - A pull request performs a dry-run build of both packages without publishing

### t14 — \[tumbler\] Browser test harness: three host fixtures (plain page calling mount/update, web-component page served with script-src 'self', standalone page) driven headlessly with the network log captured

- depends on: t10, t11
- covers: c16, h13, h2, h4, h20, h19
- acceptance:
  - For each of the three forms the captured network log contains zero requests to any origin other than the test server's
  - The web-component fixture renders under a Content-Security-Policy of script-src 'self' with no violation reported
  - A scan equivalent to embodiment's check-no-external-origin passes on every shipped file
  - Mounting and destroying twenty times leaves the count of live canvases, animation callbacks and observers at zero
  - An append through update() adds visible points without a page reload

### t15 — \[cli\] Producer step in embeddings-cli: a new write-gated verb that turns an Atlas with its vectors into a viewer data file, with options to leave text out and to apply an exact rotation or a stated top-k reduction

- depends on: t2
- covers: c21, h8, c8, h7, h3, h17, c29, c4
- acceptance:
  - It previews by default, writes only with --apply, refuses an existing target without --force, writes atomically, and refuses an Atlas with no vector file with a hint naming 'embeddings survey'
  - The output passes the contract fixtures' rules, copies model, endpoint, seed, limitations and uncertain into provenance, and its size is within 5% of points x dimensions x 4 bytes plus the records
  - A labels-only option produces a file containing no corpus text
  - Exact rotation preserves all pairwise distances to 1e-5; top-k is off unless requested and records directions kept and variance dropped
  - 'embeddings map --html' output is byte-identical before and after for the same Atlas, no file under embeddings/atlas or the stable-contract modules changes, and the roadmap lockstep test, explain, learn, README and the version bump are in place

### t16 — \[both\] Real-Atlas proof: survey at least 300 texts live through the lobes gateway (key via grant run), produce the data file, run the three forms on it, and record the measurements and what was and was not seen

- depends on: t11, t14, t15
- covers: c1, h1, c15, h12, c32, h22, h15, h16, h9, c16, h13, h8
- acceptance:
  - A script kept in the repo computes Tumble's mean group separation on the real data file and the random-frame baseline; the result is recorded and compared with the 1.3 target
  - The page's logged frame rate with 10,000 real 1024-d points on the user's desktop is recorded and compared with the 30 fps target
  - The network logs for all three forms on the real data show zero foreign requests
  - An evidence document states which structures are visible in motion that the 2-D 'embeddings map' of the same Atlas hides or merges, or states plainly that none was found
  - The gateway key appears in no file, log or page produced by the run

### t17 — \[tumbler\] Reference comparison: a written list of every intended difference from the reference demo, and a side-by-side check on the sample set that the user signs off

- depends on: t11
- covers: h14, c22
- acceptance:
  - docs/reference-differences.md lists each intended difference, starting with fonts, and nothing else differs in the three modes' look on the sample set
  - The user's sign-off of the side-by-side comparison is recorded before the first release

### t18 — \[tumbler\] Documentation for the two outside readers: a host integration guide (script, web component, standalone page, theming, lifecycle) and a producer guide, tested by a second producer written only from the guide

- depends on: t8, t12
- covers: c12, h3, h9
- acceptance:
  - The host guide shows a complete working page for each delivery form, and each example is exercised by the browser harness
  - A stdlib-only script written from the producer guide alone, not sharing code with embeddings-cli, emits a data file the loader accepts
  - The guides state that the data file carries text and vectors and how to leave text out

## Risks

- [unknown_nonblocking] The single core file is assembled from several source modules by a small in-repo script. The spec says no build step is needed to USE the file; this plan reads that as allowing an assembly step for developers. If the user wants one hand-written file instead, tasks t4-t8 collapse into one and cannot run in parallel. (task t3)
- [unknown_nonblocking] Whether npm lets a trusted publisher be attached before a package's first publish, the exact scope string for the culture.dev organisation, and whether the name is free are unverified; the first npm release may need a one-time token publish from grant. (task t13)
- [unknown_nonblocking] Keeping the PyPI and npm releases in step adds JavaScript tooling and a second publish job to a repo whose CI is pytest-only. (task t13)
- [unknown_nonblocking] Appending points shifts the cloud's centre, scale and true-neighbour sets; absorbing that without a visible jump, and its cost per append, is unmeasured. (task t8)
- [unknown_nonblocking] Headless browsers in CI may have no GPU; the WebGL 2 render tests may need a software renderer or have to run only locally. Only desktop Chrome has been looked at; Firefox, Safari and phones are unexamined. (task t14)
- [unknown_nonblocking] The 30 fps target with 10,000 x 1024-d points is unmeasured; the reference handled 12,288 x 384-d. If it is missed, the options are the opt-in top-k reduction or measuring fewer neighbours. (task t16)
- [unknown_nonblocking] The producer verb's name in embeddings-cli is not chosen; it must read as a global verb or a noun with an overview to pass the rubric. (task t15)
- [unknown_nonblocking] Work spans two repos: the plan lives in embeddings-cli but seventeen of eighteen tasks build in embeddings-tumbler. The workforce run needs both checkouts, and the embeddings-cli PR needs its own version bump.
- [follow_up] Later sources are not planned here: embodiment's vector route and dashboard view, eidetic-cli export, image embedding, the single-embedding view, a text alternative to the canvas, and the innereye interchange format.
